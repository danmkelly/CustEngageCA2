Framework 5 — Fogg Behaviour Model: B=MAP (Fogg 2009)

Behaviour = Motivation × Ability × Prompt. All three must converge at the same moment for a behaviour to occur. Applied to chatbot purchase flow.

IDFactorAssessmentStatus
A22MotivationProduct cards show price, OFF badges, offers. Detail view adds stock level, description, food facts. Chat suggests pairings and meal ideas. Sensation (product images, category icons) and anticipation (discount labels, 'representative image') drive motivation.PASS
A23Ability (Simplicity)One-click product → detail. Quantity selector (+/-). Single 'Add to Basket' button. Basket accessible from brand bar. No multi-page checkout — just click, add, review, confirm. Friction is minimised at every step.PASS
A24Prompt (Trigger)Quick-reply suggestions ('What's on special offer?', 'Keep shopping') act as hot triggers. Filter pills prompt exploration. Chat product links are clickable. 'Keep shopping' after purchase returns user to catalogue. The persistent human ramp is a spark for anxious users.PASS

The Emerald Pantry chatbot scores highly on all three Fogg factors. The purchase flow is optimised for simplicity: discover → click → adjust quantity → add → review → checkout. The Prompt dimension is particularly strong with multiple trigger types (suggestions, links, pills, basket icon). Suggested improvement: add a timed prompt after idle ('Still browsing? Here's what's new this week') to re-engage.

The PEAS specification reveals that Ember operates in a well-defined environment with clear performance metrics. A suggested enhancement: add explicit performance tracking (product click-through rate, basket abandonment) to close the measurement loop.

Framework 9 — BDI Model: Beliefs, Desires, Intentions (Bratman 1987 / Rao & Georgeff 1995)

Agent architecture where behaviour emerges from Beliefs (what the agent knows), Desires (what it wants to achieve), and Intentions (what it commits to doing).

IDBDI ComponentAssessmentStatus
B10Beliefs (Knowledge)Live product catalogue (30 items from Google Sheets). Nutritional data + allergens from OpenFoodFacts (via worker enrichment). Customer identity (name, preferences, visit history from localStorage). Conversation history (last 20 exchanges). Filter state (active category, active filters, sort). Basket contents. The belief base is grounded in verifiable external sources.PASS
B11Desires (Goals)Primary: help customer discover products → facilitate purchase. Secondary: be conversational and warm, respect consent/privacy, handle off-topic gracefully, present accurate data. The system prompt encodes these as behavioural desiderata.PASS
B12Intentions (Commitments)Onboarding flow is an intention stack: Bot/Human → consent → name → unlock. Search intent triggers catalogue lookup + LLM response. Filter intent triggers client-side pre-filter + re-render. Purchase intent opens detail view → basket → checkout. Intentions are persistent across turns (filter state survives browsing, basket persists until cleared/checked out).PASS

The Emerald Pantry chatbot implements a practical BDI architecture without explicitly modelling it as such. The clear separation between data (Beliefs), system prompt goals (Desires), and conversation state (Intentions) makes the agent's behaviour explainable and auditable. A suggested enhancement: formalise the BDI structure in documentation for easier academic defence.
